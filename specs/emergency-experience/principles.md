# 긴급 상황의 경험 spec v0.1

상태: 구현·검토용 제안. 사용자가 2026-11-05 상황 spec과 storyboard를 함께 만드는 범위를 선택하였다. 안전 안내의 적합성이나 기관 연계가 승인되었다는 뜻은 아니다.

## 목표

사고 직후 사용자가 긴 문장을 읽지 않고 핵심 상황·다음 행동·미확인을 구별할 수 있는지 확인한다. 기존 통합 flow의 SC01·SC03·SC05를 바탕으로 시각 indicator와 짧은 label을 사용하는 storyboard를 만든다.

## 접근과 범위

- Storyboard만 만드는 방식은 빠르지만 상태와 시각 표현의 관계를 반복 검토하기 어렵다.
- 선택한 방식은 상황 spec을 storyboard의 실행 data로 사용한다. `scenarios.json`이 장면·전이·문구·출처의 정본이다. JSON을 사용해 별도 YAML parser 없이 React에서 읽고 이후 Kotlin에서도 읽을 수 있게 한다.
- 이전 네 design tool 적용안은 비교 자료로 보존한다. 이번 결과를 네 도구의 성능 평가로 해석하지 않는다.
- 최종 제품은 Kotlin + Compose이다. 이번 구현은 기존 React/Vite prototype에 `?study=emergency`로 추가한다.

## 표현 원칙

1. 핵심 상황을 의미 있는 indicator와 짧은 label로 나타낸다. Icon만으로 이해된다고 가정하지 않는다.
2. 한 장면에서 실제로 선택할 주 행동은 최대 하나다. 시연용 외부 event와 장면 선택은 차량 화면 밖에 둔다.
3. 정보의 미확인과 위험 없음은 다르다. 색·형태·문구를 함께 사용한다.
4. 차량 이동 가능은 운전자 조작 가능·이동 경로 안전과 별개다. 어느 하나라도 미확인이면 이동 허용을 그리지 않는다.
5. 응답 없음으로 의식·부상을 판정하지 않는다. 응답이 없으면 구호 연결만 countdown 뒤 자동으로 진행한다. 차량 지원·보험은 자동으로 요청하지 않는다(2026-11-08 사용자 결정).
6. 통화 연결·요청 전송·기관 접수를 각각 구별한다. 기관 하나의 접수가 전체 완료나 안전 확보가 아니다.
7. 사람 symbol은 특정 탑승자·좌석·신체 부위를 나타내지 않는다. 현장 geometry와 부상 위치를 알 수 없으므로 실제 감지 그림을 만들지 않는다.
8. 보험·경위 기록 등 후속 정보는 긴급 주 행동과 같은 비중으로 제시하지 않는다. 검토용 spec에서 전체 상태를 확인할 수 있다.
9. 사용자가 화면을 볼 수 있는지, 조작할 수 있는지 확인되지 않았다. 응답 가능한 경로와 응답이 없는 경로를 각각 시연한다.
10. 상태는 실제 입력 또는 명시된 시연 event로만 바뀐다. 장식 motion이나 시간 경과가 상태를 바꾸지 않는다. 구호 countdown 만료만 예외다(2026-11-08 사용자 결정).
11. 모든 장면은 ① 차가 감지한 것, ② 차가 할 일, ③ 운전자가 지금 할 행동을 같은 자리에 둔다. ③의 안전 안내는 공개 지침을 근거로 한 시안이며 승인 전이다(2026-11-08 사용자 결정).

## 근거와 결정 경계

- [통합 flow 검토](../../docs/reviews/flow-review-v1.2.md)의 D01–D05는 계속 미결정이다. 이번 시연은 그 운영 정책을 확정하지 않는다.
- 구호 자동 연결은 PoC의 시연 결정이다. D02(연락·자동화 범위)는 운영 정책으로 계속 미결정이다(2026-11-08).
- D01: 실제 이동 판단 주체와 조건. D02: 긴급 연락·정보 전송·자동화 범위. D03: 결과 조회·중복 방지·재시도 조건. D04: 실제 중단·재개와 저장 범위. D05: 인계·지원 종료 조건.
- 가상 통화 연결·접수 확인은 검토자가 공급하는 event다. UI의 tap만으로 기관 접수를 확정하지 않는다.
- Google의 [interaction principles](https://developers.google.com/cars/design/design-foundations/interaction-principles), [writing principles](https://developers.google.com/cars/design/design-foundations/writing-principles)를 정보 우선순위와 짧은 문구의 참고로 사용한다. 사고 상황에서의 이해도 검증을 대신하지 않는다.

## 산출물

`scenarios.json`은 실행 data, `visual-language.md`는 표현 규칙, `acceptance.md`는 검사와 사용자 평가 절차다. Storyboard의 spec 보기에서 현재 장면의 source node·미결정 사항·숨긴 정보·가상 상태를 확인한다. 화면은 spec의 문구와 상태를 직접 사용한다.

Scenario의 `presentation`은 화면에 보일 사실·기관을 명시한다. SC01에서는 운전자·경로 미확인과 구호 상태를, SC03에서는 부상·의식 미확인과 구호 상태를, SC05에서는 세 기관 상태와 도착·인계 미확인을 우선한다. 다른 사실·요청 상태도 manifest와 spec 보기에 보존한다.
