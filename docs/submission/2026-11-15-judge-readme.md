# 차분: 심사자용 실행 안내

차분은 사고 직후 운전자가 Pleos 차량 화면에서 먼저 안전을 확인하고, 필요하면 직접 119에 연결하고, 사고 내용을 남겨 보험사에 보낼 범위까지 스스로 정리하도록 돕는 차량용 앱이다.

이 문서는 저장소 루트 README에 옮길 원고다. 기울임꼴 괄호 *( )* 부분은 최종 제출 직전에 실제 값으로 바꾼다.

## 제출 APK는 차량 단독으로 동작한다

제출 APK 하나만 설치하면 차량 흐름 전체를 실행할 수 있다. 서버, 인터넷 연결, 휴대폰은 필요하지 않다. 사고 기록은 차량 앱 안에 저장한다.

| 구성 | 설명 | 제출 APK |
| --- | --- | --- |
| Pleos 차량 앱 | Kotlin Native 앱이 Pleos Vehicle SDK와 119 다이얼을 맡는다. 화면은 APK에 함께 넣은 웹 UI를 WebView로 띄운다. 화면 파일은 인터넷에서 받지 않는다 | 포함 |
| 휴대폰 이어받기 | 차량 화면의 QR로 휴대폰에서 같은 사고 기록을 열고 사진, 음성, 진술, 경위서를 남긴다. 사고 기록 서버가 필요하다 | 꺼져 있음. 시연 영상과 2차 PT에서 보여 줌 |

휴대폰 이어받기는 소스에 있는 실제 기능이다. 제출 APK는 서버 주소 없이 빌드했기 때문에 `휴대폰으로 남기기` 탭과 휴대폰 연결 화면이 나타나지 않는다. 시연 영상에서는 개발 장비에서 실행한 서버를 Cloudflare 터널의 HTTPS 주소로 열고, 그 주소로 빌드한 APK를 사용했다.

## 테스트 환경

| 항목 | 값 |
| --- | --- |
| 에뮬레이터 | Pleos Connect Emulator v2.1.0, Android API 34, arm64-v8a 시스템 이미지 |
| 화면 규격 | Connect Standard 2560×1440 가로 |
| 앱 창 | 1682×1210 (x 853–2535, y 90–1300). 화면 분할 시 약 841×1210 |
| Pleos SDK | `ai.pleos.playground:Vehicle:2.3.2` |
| 앱 빌드 | 앱 ID `com.chabun.vehicle`, minSdk 28, targetSdk 35, compileSdk 35, JDK 21, Gradle wrapper |
| 개발 호스트 | macOS, Apple Silicon (arm64), Android Studio 내장 JBR 21 |

공식 Pleos 시스템 이미지가 아닌 일반 Google APIs 에뮬레이터에서는 Pleos SDK 서비스가 없으므로 에어백 신호가 "미지원"으로 표시된다.

## 실행 방법

### 1. Pleos Connect 에뮬레이터 준비

Pleos 개발 문서의 [Connect SDK 에뮬레이터 설치 안내](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator)에 따라 Pleos Connect Emulator v2.1.0 (API 34, arm64) 이미지를 설치하고 실행한다.

실행 중인 에뮬레이터를 확인한다.

```sh
adb devices
adb -s <에뮬레이터 serial> shell getprop ro.build.version.sdk
```

두 번째 명령의 출력은 `34`여야 한다.

### 2. APK 설치와 실행

```sh
adb -s <에뮬레이터 serial> install -r apk/팀명_앱이름_release.apk
adb -s <에뮬레이터 serial> shell am start -n com.chabun.vehicle/com.example.accidentpoc.MainActivity
```

*(APK 파일명은 최종 빌드 기준으로 바꾼다.)* 런처에서는 **차분** 아이콘으로 실행할 수 있다.

같은 앱 ID의 debug 빌드가 이미 설치돼 있으면 서명이 달라 설치가 거절된다. 이때는 debug 앱을 먼저 지운다.

```sh
adb -s <에뮬레이터 serial> uninstall com.chabun.vehicle
```

앱은 Pleos 앱 창 안에서만 그린다. 왼쪽 Driving view, 상태 표시줄, GNB는 시스템 영역이다.

### 3. 시연 조작 열기

에뮬레이터에서 만들 수 없는 입력과 외부 결과는 앱 창의 `시연` 버튼으로 넣는다. 누르면 시연 조작이 펼쳐지고 다시 누르면 접힌다. 여기서 넣은 값은 화면에 `시연` 또는 `예시 자료`로 표시되며 실제 센서나 기관의 결과가 아니다.

| 시연 조작 | 결과 |
| --- | --- |
| `새 시연 시작` | 새 사고 기록으로 처음부터 시작 |
| `에어백 전개 신호` | 에어백 전개 관찰을 추가. 첫 질문이 "에어백이 펼쳐졌어요"로 바뀌고 119 칸이 나타남 |
| `위험 정보` | 새 위험 관찰을 추가. 안내 칸이 "주변을 다시 살펴보세요"로 바뀜 |
| `보험사 전송 완료`, `보험사 전송 실패` | 보내는 중인 요청의 전송 결과 |
| `보험사 접수 확인` | 보험사 접수 결과 |
| `음성 입력` → `준비된 음성 sample` | 마이크 대신 준비된 음성 파일로 음성 기록을 만듦 |

## 확인할 수 있는 흐름

### 대표 흐름: 일반도로의 경미한 접촉 사고

1. 첫 화면에서 "다친 사람이나 위험한 상황이 있나요?"를 확인한다. 이 단계에서는 119 칸이 없다.
2. `급한 위험은 없어요`를 누른다.
3. 대피 체크리스트(비상등 켜기, 트렁크 열기, 대피할 곳 찾기, 휴대폰 챙기기)를 체크하고 `안전한 곳에 있어요`를 누른다.
4. `기록 시작`을 누른다. 가운데 칸이 "어떻게 부딪혔나요?"를 묻고 오른쪽 기록 칸이 넓어진다.
5. `말로 남기기`에서 내용을 직접 입력하고 `기록 저장`을 누른다. 녹음에는 마이크가 필요하다. Pleos 에뮬레이터는 기본 설정에서 호스트 마이크를 넘기지 않으므로 녹음이 0:00으로 저장된다. 녹음 기능은 시연 영상에서 보여 준다.
6. `남긴 내용 확인`을 누른다. 기록을 저장해야 이 버튼이 활성화된다.
7. 받는 곳 `보험사 접수`와 보낼 자료를 고르고 미리 본 뒤 승인한다.
8. `승인한 내용 보내기`를 누른다. 화면이 "기록을 보내고 있어요"로 바뀐다.
9. `시연` 조작의 `보험사 전송 완료`를 누른다. 상태가 "보험사 접수 미확인"으로 남는다. `보험사 접수 확인`을 눌러야 "보험사 접수 확인"으로 바뀐다.

### 분기

| 흐름 | 조작 |
| --- | --- |
| 긴급 상황 | 첫 질문에서 `다친 사람이 있거나 위험해요`를 누른다. 가운데 열 위쪽에 119 칸이 나타난다. `119에 연결`을 누르면 전화 앱에 `119`가 채워진 채 열린다. 통화 버튼은 누르지 않는다. 앱은 자동으로 발신하지 않는다 |
| 에어백 신호 | `새 시연 시작` 뒤 `에어백 전개 신호`를 누른다. 첫 질문이 "에어백이 펼쳐졌어요"로 바뀌고 119 칸이 나타난다 |
| 기록 보류 | 기록 단계에서 아무것도 저장하지 않고 `나중에 기록할게요`를 누른다. 기록 없이 이후 할 일로 넘어간다 |
| 새 위험 후 복귀 | 기록 단계에서 내용을 입력하는 도중 `위험 정보`를 누른다. 안내가 "주변을 다시 살펴보세요"로 바뀐다. `주변을 확인했어요`를 누른 뒤 `기록 시작`을 누르면 입력하던 내용이 그대로 있다 |
| 전송 보류·거절 | 검토 단계에서 `나중에 결정` 또는 `전송하지 않기`를 누른다. 기록은 유지된다 |
| 전송 실패 | 보내는 중에 `보험사 전송 실패`를 누른다. "보내지 못했어요"와 `다시 보내기`가 나온다 |

## 에어백 신호

앱은 Vehicle SDK `Safety`의 좌석별 에어백 전개 capability를 확인하고, 지원 좌석의 값을 조회·구독한다. `pleos.car.permission.CAR_SAFETY` 권한이 필요하다.

- 에뮬레이터에서 받은 값은 출처를 `시뮬레이션`으로 표시한다. 실차 신호로 표시하지 않는다.
- 권한 없음, 미지원, 차량 서비스 연결 실패, 읽기 실패는 각각 "신호 확인 불가" 상태로 표시한다. "사고 없음"으로 바꾸지 않는다.
- 전개 신호가 들어오면 첫 질문이 "에어백이 펼쳐졌어요"로 바뀌고 119 칸이 나타난다. 이때도 전화는 운전자가 눌러야 연결된다.

## 제한 사항

- **휴대폰 이어받기.** 제출 APK에서는 꺼져 있다. 사고 기록 서버가 필요하며 시연 영상과 2차 PT에서만 보여 준다. 휴대폰에서의 사진 촬영, 경위서 수정, 내 기록 사본 내려받기도 같은 이유로 시연 영상에서만 볼 수 있다.
- **사진.** 에뮬레이터에는 차량 카메라가 없다. 차량 화면의 `사진 남기기`에서는 대상별로 생략을 고를 수 있다. 사진은 휴대폰 이어받기에서 찍는다.
- **충돌 자동 감지.** 현재 자동 입력은 Vehicle SDK 에어백 전개 신호뿐이다. 에어백이 펼쳐지지 않는 경미 사고는 감지하지 못하며, 운전자가 앱을 열어 시작한다. 실차에서의 에어백 신호 수신은 검증하지 않았다.
- **앱 자동 실행 없음.** 에어백 신호가 와도 앱이 꺼져 있으면 자동으로 열리지 않는다.
- **119.** 앱은 전화 앱을 열 뿐 발신·신고·접수를 하지 않는다. Pleos 에뮬레이터에서는 전화 앱이 `119`가 채워진 채 열린다. 실차에서는 Pleos 하드웨어 정책상 전화 기능이 제한될 수 있다. 구호 접수 상태는 `시연` 입력 없이는 "미확인"으로 남는다.
- **보험사.** 실제 보험사 API와 연결돼 있지 않다. 보험사 전송·접수 상태는 `시연` 입력으로만 바뀐다.
- **블랙박스·카메라·Fleet.** 블랙박스 영상, 차량 카메라, Fleet API 충돌 상태는 연동하지 않았다.
- **시연 자료.** 주변 상황 그림의 차량 위치·충격 위치 같은 예시 값은 `시연`·`예시 자료`로 표시한다. 실제 센서 값이 아니다.
- **음성.** 안내 음성은 미리 생성한 파일을 재생한다. 음성 기록은 오디오 파일로만 저장하며 텍스트 변환은 하지 않는다. 외부 음성 인식 서비스로 보내지 않는다.
- **실차.** 실차와 실제 Pleos 차량 서비스에서 검증하지 않았다. 검증 환경은 공식 Pleos Connect 에뮬레이터다.

## 소스 위치

| 경로 | 내용 |
| --- | --- |
| `prototype/android/` | Pleos 차량 앱 (Kotlin, WebView 호스트, Vehicle SDK 연동) |
| `prototype/web/src/` | 차량 화면 UI와 휴대폰 화면 (React, TypeScript) |
| `prototype/web/server/` | 휴대폰 이어받기용 사고 기록 서버 (Bun, SQLite). 제출 APK는 사용하지 않음 |
| `specs/emergency-experience/` | 장면·문구·음성 원고 정본 |
| `apk/` | 제출 release APK *(최종 파일명 기재)* |

## 직접 빌드하기

차량 화면 번들을 먼저 만든다. Gradle 빌드는 `prototype/web/dist-native/`를 APK에 복사하며, 이 폴더가 없으면 빌드가 실패한다.

```sh
cd prototype/web
npm ci
npm run build:native
```

저장소 루트에서 차량 단독 release APK를 만든다. 서명 키는 저장소 밖에 두며 절차는 [`prototype/android/README.md`](../../prototype/android/README.md)에 있다.

```sh
./prototype/android/release.sh <서명 env 파일> standalone <출력 APK 경로>
```

휴대폰 이어받기를 켜려면 `standalone` 대신 사고 기록 서버의 HTTPS 주소를 넣는다. 서버 실행 방법도 같은 README에 있다.

웹 검사는 다음 명령으로 실행한다.

```sh
cd prototype/web
npm run check
npm run test:ui
```
