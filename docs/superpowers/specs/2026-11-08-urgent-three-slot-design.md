# 긴급 화면 세 칸 구조와 긴박도 설계

2026-11-08. 대상: `?study=emergency` 차량 화면(web storyboard). 시안: [urgency-directions.png](2026-11-08-urgent-three-slot/urgency-directions.png) · [fragment](2026-11-08-urgent-three-slot/urgency-directions.fragment.html).

## 의도

사용자 판단(2026-11-08): 실제 사고 직후의 운전자는 놀랐거나 다쳤고, 글을 읽거나 따져 볼 시간이 없다. 그런데 지금 화면은 정돈된 상태 표시판처럼 차분하다. 실제 상황과 화면 사이에 차이가 있다.

원인은 네 가지로 보았다.

1. Spec이 긴박감을 만드는 수단을 금지했다. 깜빡임·countdown·등장 motion을 쓰지 않고, 확인 상태에서도 색을 neutral로 둔다.
2. 시선이 갈 곳이 다섯 군데쯤이다. 큰 symbol, 제목, button, 사실, 기관 상태 줄이다.
3. 문구가 설명조다(`차량 지원 접수를 확인하세요`).
4. 금속 각인과 Satin이 화면을 더 고요하게 만들었다.

목표는 화면이 세 질문에 즉시 답하는 것이다.

- **① 감지**: 차가 무엇을 파악했고, 무엇을 아직 모르는가.
- **② 차량**: 차가 다음에 무엇을 하는가. 운전자 승인이 필요한가.
- **③ 나**: 운전자가 지금 할 행동 하나.

## 성공 기준

처음 보는 사람이 화면을 **3초** 보고 "지금 할 일"을 말한다(사용자 결정). 절차는 [acceptance.md](../../../specs/emergency-experience/acceptance.md)의 「사용자 이해도 평가」를 따른다. 3초는 탐색 조건이며 안전 기준이 아니다. 이번 구현은 그 평가를 할 수 있는 화면과 도구를 만드는 데까지다. 평가 결과를 만들어 넣지 않는다.

## 사용자가 정한 것

1. **세 칸 구조**: 모든 장면이 ① 감지 / ② 차량 / ③ 나의 세 칸을 같은 자리에 둔다.
2. **안전 안내 포함**: ③에 운전자 행동을 직접 쓴다.
3. **승인이 기본이다. 응답이 없으면 구호만 자동으로 진행한다.**
   - 차의 다음 행동은 운전자가 승인해야 진행한다.
   - 운전자가 응답하지 않으면 **구호(119) 연결만** 자동으로 진행한다. 정신이 없거나, 크게 다쳤거나, 의식이 없는 경우를 위한 것이다.
   - 차량 지원과 보험은 자동으로 진행하지 않는다.
4. **시각 방향 B · 어둠 속 한 점**: 화면은 어둡게 두고, 지금 결정할 것 하나만 강하게 표시한다. 긴박도는 상태를 따라 내려간다. 화면 전체를 경보색으로 칠하는 A는 고르지 않았다.

## 목표 · 비목표 · 안티목표

**목표**

- 세 scenario(SC01·SC03·SC05)의 모든 장면을 세 칸 구조로 다시 짠다.
- 구호 자동 연결 흐름(countdown → 자동 연결)을 SC01·SC03에 넣는다.
- 3초 노출 평가를 할 수 있는 검토 도구를 둔다.

**비목표**

- Compose 이식. Web storyboard를 사용자가 확인한 뒤 별도 plan으로 SC05부터 갱신한다.
- 실제 전화·전송, 차량 비상등 제어, 음성 인식, 차량 sensor 판단.
- 안전 안내 문구의 최종 승인. 이번 문구는 공개 지침을 근거로 한 시안이다.
- 운영 정책 D02(연락·자동화 범위)의 확정. 이번 결정은 PoC 범위의 결정이다.

**안티목표** (기술적으로 동작해도 실패로 본다)

- 화면 전체를 경보색으로 칠하거나 깜빡이게 하는 것. 놀란 사람을 얼어붙게 할 수 있다.
- 한 장면에 강조색 요소가 둘 이상인 것.
- 초록 "완료" 화면이나 "안전합니다" 같은 표현. 구호가 도착하지 않았다.
- 응답 없음을 `의식 없음`으로 표현하는 것.
- 차량 지원이나 보험을 자동으로 요청하는 것.
- ③이 문장이 되는 것.

## 화면 구조

1440 × 810 canvas, 위에서 아래로 세 칸이다. 시안의 비율(① 150 px / ② 나머지 / ③ 170 px)을 시작값으로 둔다.

| 칸 | 내용 | 규칙 |
| --- | --- | --- |
| ① 감지 | 장면 cue glyph(금속 plate) + 감지 label + 미확인 사실 chip | Label은 짧은 명사구(`충돌 감지 · 부상 있음`). `visible_facts`는 작은 chip(`? 운전자 조작`)으로 남긴다. 이동 가능과 이동 허용을 섞지 않는 원칙은 그대로다. |
| ② 차량 | 차가 할 일 한 문장 + 필요한 경우 승인 button + 기관 상태 한 줄 | 제목은 차를 주어로 한 짧은 서술(`119에 연결합니다`, `119 연결 중`). 기관 상태 줄은 `구호 ✓ 접수 확인 · 차량 지원 ? 접수 미확인 · 보험 ○ 요청 전` 형식이다. 상태 표식(금속 mark)과 label을 쓴다. 지금의 하단 `지원 현황` 줄을 대신한다. |
| ③ 나 | 지금 할 행동 하나. 동사로 끝나는 1–3 어절 | 가장 큰 글자는 ②의 제목과 ③이다. 다음 단계는 `→` 뒤에 하나까지 작게 보인다. |

기존 `instruction`·`detail` 같은 보조 문장은 화면에서 빼고, spec 보기와 음성 원고에 남긴다.

## 긴박도 색 규칙

| 단계 | 쓰는 곳 | 색(시작값) |
| --- | --- | --- |
| 결정 필요 | **구호 연결 결정**(countdown ring·숫자, `지금 연결` button)에만 쓴다 | 빨강 `#FF453A` |
| 차가 진행 중 | 연결 중·확인 중인 ②의 표시 | 호박 `#FFB340` |
| 대기·확인됨 | 그 외. 확인 표식만 기존 mint | neutral |

- 빨강은 생명과 관련된 결정에만 쓴다. 차량 지원·보험의 승인 button은 neutral의 주 button이다(제 판단: 빨강이 흔해지면 효과가 사라진다).
- 한 장면에 빨강 요소 묶음은 하나다.
- 색만으로 뜻을 전하지 않는다. Countdown 숫자, `연결 중` 문구, 상태 표식 모양이 함께 있다.
- Text 대비: 일반 글자 4.5:1, 큰 글자(24 px 이상 또는 18.66 px 이상 굵게) 3:1. 빨강 button의 흰 글자는 큰 굵은 글자로만 쓴다.

## 구호 자동 연결

**적용 조건**: 구호 상태가 `not_sent`이고 운전자 응답을 기다리는 장면.

**Countdown**
- 길이는 10초. `scenarios.json`의 값으로 두어 조정할 수 있게 한다(제 판단: 시작값).
- ②에 `119에 연결합니다`, 남은 초 숫자와 ring, `응답이 없으면 N초 후 자동 연결`을 보여 준다.
- Button은 `지금 연결`과 `취소` 두 개다. 둘 다 운전자의 응답으로 본다.
- 오조작 방지: 화면의 다른 곳을 눌러도 취소되지 않는다. 취소는 `취소` button으로만 한다.

**Button과 만료 결과**

| 입력 | 결과 |
| --- | --- |
| `지금 연결` | 바로 구호 연결 흐름(`connection_unknown`)으로 간다. |
| `취소` | 구호를 보내지 않는다. ②에 `구호 연결 안 함`과 `다시 연결` button을 남긴다. 실수로 취소했을 때 되돌릴 길이다. `다시 연결`은 countdown 없이 바로 연결한다. |
| 만료 | 구호 연결 흐름으로 간다. ②는 `119 연결 중`과 `응답이 없어 자동으로 연결했어요`를 보여 준다. ①은 `? 운전자 응답 없음`이다. 의식·부상 상태는 계속 미확인으로 둔다. |

**만료 뒤의 응답**: 자동 연결 뒤에도 운전자가 응답할 수 있는 control(`응답할 수 있어요`)을 ③에 남긴다.

**소리**: Countdown이 시작되면 경고음을 내고, 음성으로 "응답이 없으면 10초 후 119에 연결합니다"를 한 번 읽는다. Browser가 자동 재생을 막으면 화면 문구만으로 진행하고, 검토 UI에 소리가 막혔다고 표시한다.

**Motion**: Countdown ring과 숫자 갱신만 움직인다. `prefers-reduced-motion`에서는 ring을 1초 단위로 끊어 갱신한다. 깜빡임은 쓰지 않는다.

**시연 제어**
- 검토 UI의 일시 중단은 countdown도 멈춘다.
- 장면에 다시 들어오면 countdown은 처음부터 시작한다.
- 검토자 event `응답 없음 (즉시)`로 만료를 바로 일으킬 수 있다.

**접근성**: 장면 전환과 자동 연결은 live region으로 알린다. Countdown의 초 단위 갱신은 읽지 않는다. 시작과 만료만 알린다.

## Scenario별 흐름

기존 장면 ID는 유지하고, 필요한 장면만 추가한다. 상태 이름은 구현자가 정해도 된다.

| Scenario | 장면 | ① 감지 | ② 차량 | ③ 나 (시안) |
| --- | --- | --- | --- | --- |
| SC01 | initial | 충돌 감지 · 부상 있음 / ? 운전자 조작 · ? 이동 경로 | **countdown** `119에 연결합니다` | 비상등 켜기 → 트렁크 열기 |
| SC01 | (취소) | 같음 | `구호 연결 안 함` + `다시 연결` | 비상등 켜기 |
| SC01 | contact_unknown | 같음 | 호박 `119 연결 중` (자동이면 사유 한 줄) | 움직일 수 있으면 가드레일 밖으로 |
| SC01 | connected | 같음 | 호박 `119 통화 연결됨 · 접수 미확인` | 가드레일 밖으로 |
| SC03 | initial | 충돌 감지 · ? 응답 미확인 / ? 부상 · ? 의식 | **countdown** `119에 연결합니다` | 비상등 켜기 |
| SC03 | unanswered | 충돌 감지 · ? 운전자 응답 없음 | 호박 `119 연결 중` · `응답이 없어 자동으로 연결했어요` | `응답할 수 있어요` |
| SC03 | responded | 응답 확인 · ? 부상 · ? 의식 | `취소`에서 왔으면 `구호 연결 안 함` + `다시 연결`, `지금 연결`에서 왔으면 `119 연결 중` | 비상등 켜기 |
| SC05 | initial | 차량 지원 · ? 접수 미확인 / ? 현장 도착 · ? 구호 인계 | neutral `차량 지원 접수 미확인` + `요청 상태 확인` | 안전한 곳에서 대기 |
| SC05 | checking | 같음 | 호박 `차량 지원 접수 확인 중` | 안전한 곳에서 대기 |
| SC05 | received | 차량 지원 접수 확인 / ? 도착 · ? 인계 | neutral `차량 지원 접수 확인` | 안전한 곳에서 대기 |

- SC05에는 countdown이 없다. 구호가 이미 `received`이기 때문이다.
- SC03의 기존 `응답할 수 있어요`는 countdown의 두 button과 만료 뒤의 ③으로 나뉜다. 응답 없음은 이제 시간 만료로 생긴다. 기존 검토자 event는 `응답 없음 (즉시)`로 남긴다.

## 안전 안내(③)의 근거

한국도로공사의 2차 사고 예방 행동요령 「비트박스」를 근거로 쓴다. 순서는 **비상등 켜기 → 트렁크 열기 → 가드레일 밖으로 대피 → 신고**다. 2018년부터 대피를 신고보다 먼저 하도록 바뀌었다.

- 신고는 ②의 구호 연결이 대신하므로 ③에 쓰지 않는다.
- 부상 장면(SC01)에서는 대피 앞에 `움직일 수 있으면`을 붙인다.
- 장면별 문구는 위 표의 시안이다. 화면 밖 검토 UI에 `안전 안내 시안 · 승인 전`을 표시한다.
- 문구와 출처는 `scenarios.json`의 각 장면(`self_action` 같은 field)과 spec 보기에 남긴다.
- 출처: [보안뉴스 — 도로공사 '비트박스'](https://m.boannews.com/html/detail.html?idx=128068), [korea.kr](https://www.korea.kr/news/reporterView.do?newsId=148931463). 구현 전 한국도로공사 공식 자료로 다시 확인한다.

## 재질과 pictogram

- 금속 각인 glyph는 ①의 cue와 사실 chip, ②의 기관 상태 표식에 쓴다. ①의 cue 크기는 지금(174 px)보다 작게 한다(시작값 84 px plate).
- 주 행동 button의 solid glyph는 유지한다.
- Satin 배경은 기본값을 끈다. 검토 UI의 `기존 flat / C · Satin` 전환은 남긴다(제 판단: B는 어두운 단색을 기준으로 승인되었다).

## 검토 도구

- **3초 보기**: 검토 UI의 button. 차량 화면을 3초 보여 준 뒤 가린다. 평가자가 다시 누를 때까지 가린 상태를 유지한다. Acceptance의 평가 절차를 손으로 재지 않게 하기 위해서다(제 판단).
- 기존 시연 표시(`가상 scenario · 실제 전화·전송 없음`)에 `안전 안내 시안 · 승인 전`을 더한다.

## 확인할 것 (구현자가 test로 고정)

- 모든 장면에 ①·②·③ 세 칸이 있다. ③은 3 어절 이하의 동사구다.
- 빨강 요소 묶음은 구호 결정 장면에만 있고, 그 장면에서도 하나다.
- Countdown은 구호 `not_sent`의 응답 대기 장면에만 있다. SC05·차량 지원·보험에는 없다.
- 만료 → 구호 연결 흐름. ①은 `응답 없음`이고 `의식 없음`이라는 문구는 화면 어디에도 없다.
- `취소` → 연결 없음, `다시 연결` 표시. 다른 곳을 누르면 취소되지 않는다.
- 일시 중단 중에는 countdown이 줄지 않는다. 장면에 다시 들어오면 처음부터 시작한다.
- 기관 상태 줄은 세 기관을 모두 보여 주고, 기존의 기관별 독립 검사를 통과한다.
- 375 px 축소 보기, reduced motion, 흑백에서 세 칸과 상태 구별이 유지된다.
- 3초 보기가 3초 뒤 화면을 가린다.
