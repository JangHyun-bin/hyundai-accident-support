# 사고 후 대응 지원 · 통합 flow 검수본 v1.2

검토일: 2026-11-05 · 기준 commit: `f43d890`

48개 node·70개 connector를 대조하였다. 분류 결과는 유지 8개, 보완 필요 27개, 결정 필요 13개다. 보완 근거 8개와 미결정 사항 5개를 기록하였다. 기존 `project.json`의 문구·ID·위치·연결은 변경하지 않았다.

## 검토 범위

문구·연결과 다섯 scenario의 정적 논리 검토. 실제 사용자·차량·기관 동작 검증은 수행하지 않았다.

검수본 v1.2는 기존 통합 flow v1.1의 검토본이다. 제안 분기는 현재 diagram에 적용하지 않았다. 기존 연결과 제안 연결을 구분하였다. Scenario의 경로는 기존 연결의 존재 여부를 확인한 정적 검토이며, program을 실행한 시험 결과가 아니다. 실제 사고 대응의 적합성이나 효과를 확정하지 않는다.

기준 자료: [전체 board](../../project.json), [통합 graph](../../e2e/integrated-graph.json), [검토 data](../../assets/flow-review-v1.2.json), [검토 검사](../../test-review.mjs).

### SC01 · 고속도로·부상·차량 이동 가능의 동시 성립

- 고속도로 위치와 부상이 입력되었다고 가정한다.

**기대 동작**

- 부상·도로·차량 상태를 각각 유지한다.
- 확인된 위험에 대응하는 안내를 우선한다.
- 차량 이동 가능만으로 이동 안내를 제공하지 않는다.
- 허용된 기록은 가능한 범위에서 병행한다.

**구호 우선의 기존 경로**

**가능한 기록의 병행 보존**

`U1` → `P`

### SC02 · 경미한 사고·차량 이동 불가

**가정**

- 부상·즉시 위험이 없고 다음 질문을 진행할 조건이 별도로 확인되었다고 가정한다.
- 차량은 이동 불가이며 차량 지원이 필요하다.
- 경미한 사고라는 명칭만으로 안전을 확정하지 않는다.

**기대 동작**

- 직접 이동 지시는 보류한다.
- 차량 지원의 연락 안내와 실제 요청을 구분한다.
- 도움을 기다리면서 가능한 기록을 진행한다.
- 새 정보 없이 같은 이동 질문을 반복하지 않는다.

**이동 불가와 차량 지원의 기존 경로**

`U0` → `I0` → `I1` → `U1` → `S1` → `G1` → `G2` → `I4` → `G3` → `U3` → `G4` → `I4N` → `X2` → `S4`

**반복 가능성이 있는 기존 경로**

`I4N` → `G2` → `I4` → `G3` → `U3` → `G4` → `I4N`

**판정: 보완 필요**

G4의 불가·미확인에서 I4N으로 이동하는 구조는 적절하다. 보류 상태를 유지한 기록 진행과 재검토 조건이 없으면 이동 질문을 반복할 수 있다.

**보완 후 확인 사항**

I4N에서 기록으로 진행할 조건과 X2의 승인 범위를 정의한 후 같은 상태로 재진입하는 경로를 확인한다.

<a id="SC03"></a>

### SC03 · 사용자 무응답·상태 미확인

**가정**

- 초기 질문에 사용자 응답이 없다.
- 차량 정보의 제공 여부와 현장 상태는 미확인이다.
- 무응답만으로 의식 상태를 판정하지 않는다.

**기대 동작**

- 응답 없음과 부상·의식의 미확인을 구분한다.
- 명시된 조건으로 응답 재확인을 시작한다.
- 확인된 위험 정보가 있으면 응답 완료를 기다리지 않고 반영한다.
- 가능한 도움 경로와 이후 확인 주체를 명시한다.

**초기 응답 대기의 기존 경로**

`U0` → `I0` → `I1` → `U1`

**G1 미확인에 도달한 경우의 기존 경로**

`S1` → `G1` → `E1` → `I2` → `X1` → `S2` → `I3` → `U2`

**판정: 보완 필요**

E1의 무응답 ≠ 의식 없음 원칙은 유지한다. 초기 응답이 없을 때 E1에 진입할 조건과 U2에서도 응답이 없을 때의 후속 확인 주체가 필요하다.

**보완 후 확인 사항**

응답 없음 event의 진입 조건과 구호 인계 이후의 확인 주체를 정의하고 응답 없이도 유지되는 상태를 검토한다.

<a id="SC04"></a>

### SC04 · 전송 거절·보류와 이후 재개

**가정**

- 초안 사실은 확인되었고 수신처·목적·항목이 제시되었다.
- 사용자가 일반 전송을 거절하거나 보류한다.
- 다른 구호·차량 지원의 필요 여부는 각각 별도 상태다.

**기대 동작**

- 거절·보류 항목은 미전송으로 유지한다.
- 거절과 일시 보류를 구분해 표시한다.
- 가능한 다른 지원과 남은 일을 확인한다.
- 재개할 때 현재 전송 범위를 다시 제시한다.

**거절·보류 이후 상태 유지의 기존 경로**

`U6` → `I6` → `U7` → `E5` → `S8` → `I8` → `U8` → `S8B` → `G8`

**다시 확인하는 기존 경로**

`E5` → `I5B` → `U6` → `I6` → `U7`

**판정: 결정 필요**

U7의 거절·보류에서 바로 S6로 전송하지 않고 E5·S8로 진행하는 경로는 유지한다. 정정 입력으로 복귀할 경로와 보류·거절이 있을 때의 종료 조건을 명시해야 한다.

**보완 후 확인 사항**

미전송 상태를 보존한 채 필요한 다른 업무만 진행하고 재승인 없이 전송하지 않는지 확인한다.

<a id="SC05"></a>

### SC05 · 접수 미확인 이후 중단·재개

**가정**

- 승인 범위의 요청을 보냈지만 실제 접수 결과가 미확인이다.
- 사용자가 진행 중 중단한 후 다시 시작한다.
- 중단 중 외부 기관의 접수 결과가 확인될 수도 있다고 가정한다.

**기대 동작**

- 기존 요청과 결과 미확인을 보존한다.
- 중단을 외부 요청 취소로 처리하지 않는다.
- 재개 후 기존 결과를 확인하고 기접수와 미접수를 구분한다.
- 변경된 승인 범위에는 재확인을 적용한다.

**접수 미확인·중단·재개의 기존 경로**

`U7` → `S6` → `X3` → `G6` → `E6` → `S8` → `I8` → `R` → `E7` → `I0` → `I1`

**재시도의 기존 경로**

`E6` → `S6` → `X3` → `G6`

**판정: 보완 필요**

중단이 외부 요청 취소가 아니라는 E7의 원칙은 유지한다. 재개 위치와 기존 접수가 확인된 경우의 분기가 없으면 새 요청처럼 다시 진행할 수 있다.

**보완 후 확인 사항**

기접수는 I7로 진행하고 결과 미확인은 대기하며, 기존 승인 범위가 변경되면 I6에서 다시 제시하는 조건을 검토한다.

## 검토 정합성과 후속 범위

- 모든 node 분류를 원래 native ID·문구와 대조한다.
- 70개 native endpoint·문구·선 유형과 통합 graph의 일치를 확인한다.
- Scenario와 보완 근거에서 기존 경로로 제시한 모든 연결이 존재하는지 확인한다.
- 기존 문구·연결이 바뀌면 editor의 검수 분류를 재검토 필요로 표시한다. 위치 변경만으로 분류를 무효화하지 않는다.
- D01–D05의 결정 후 관련 분기와 문구를 별도 개정하고 핵심 상황의 HTML prototype으로 사용자 이해를 확인한다.

공모전 제출요강, 실제 차량·기관 연계, 안전 안내 문구와 정보 처리 조건은 이번 정적 검토에서 확정하지 않았다.
